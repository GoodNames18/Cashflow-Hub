# Cashflow Hub Web Push

`cfh-push` stores a browser subscription and calendar preference snapshot for each device. A random 256-bit device token is hashed before storage; it authorizes only that device. Push keys and the cron dispatch token are server-only in the RLS-protected `cfh_push_config` table. Public database access is revoked.

The `cfh-send-reminders` cron job invokes the authenticated dispatch route every minute. `kernel.ts` contains the calendar date rules used by the current frontend, including card estimates, recurrence, deletion scopes, overrides and bell preferences. Keep this kernel updated when calendar date rules change. The backend evaluates upcoming dates afresh each minute; it does not depend on a finite queue generated by an open browser.

The frontend uploads changed preferences after autosaves and reconnects, using the device timezone. Push delivery uses the configured notification time and selected offsets (7, 5, 3, 2, 1, 0). Schedules without a notification time are skipped. Claimed deliveries are deduplicated per device, occurrence, offset and time; failures retry with a lease and backoff. Expired subscriptions are removed.

Enable notifications in Calendar, grant browser permission, then press Test. Test sends a real server push to that device. Notification taps open Calendar. OS and browser restrictions can delay or block delivery; server scheduling has one-minute precision.

Verified: calendar recurrence and future-year generation; deletion scopes; disabled bells; cron HTTP 200 responses; public database access denied; no unauthenticated dispatch. End-to-end phone receipt requires a user-granted subscription.
